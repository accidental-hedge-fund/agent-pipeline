# Decisions live in the issue body; comments are not the spec

Agents, train, and `triage --stage ready` read the **issue body**. `pipeline grill` is the grill writer: it embeds a versioned Decisions artifact and a derived `## Decisions` section, may open a documentation PR for CONTEXT.md terms and qualifying ADRs, and may request `pipeline:ready`. `pipeline triage --stage` never edits the body. `--stage ready` is a model-free gate (exit 2, no label flip) that validates that artifact.

Root identity is title plus applied specification core (`title_sha256` and `applied_body_sha256`). Dependency closure covers declared dependencies only. `dependency_closure_sha256` hashes reachable declared-dependency issues and does not hash the root title or the root body. Pipeline-owned Decisions metadata is not a bound input: the Decisions fence, the rendered Decisions section, and handoff provenance do not change `dependency_closure_sha256`. A pre-change artifact that still records a root-inclusive closure is refreshed by `pipeline grill --issue N` when an authenticated historical pre-proposal snapshot matches the recorded hash: that path re-signs the current exclusive hash, keeps settled handoffs, and does not skip the ready fingerprint check. The current applied specification core is not that snapshot.

A comment does not settle an authority node. `settled-by: auto-accept` is provenance of an in-scope default that is reversible, policy-consistent, and covered by existing authority. It is not operator authority and never grants merge, release, destructive, security, or other protected authority. Remaining `settled-by: reviewer-accept` nodes are historical provenance of a non-authority default. Scope, security, irreversible operations, merge/release, and human-attestation stay unresolved unless auto-accept applies under existing authority or an authenticated hash-bound `pipeline handoff answer` records the settlement.

Repository-document writes use a dedicated worktree and pull request. Grill does not write the integration branch. Required documentation waits for trusted-base integration. Advisory documentation does not block admission.

#1238 owned comments are verdict evidence for the pickup-time issue-implementation-readiness gate. They are not the specification. A successful `--stage ready` label write is not a pickup bypass.

**Considered options:** store the frontier in issue comments (rejected: comments are invisible to train/body readers); interview during planning (rejected: factory must not grill mid-run); put a harness inside every `--stage ready` (rejected: complete bodies stay one deterministic call); overload bare `pipeline triage N` as the grill (rejected: living triage spec requires `--stage`; mixing grill and labels hides mutations); keep `pipeline refine-spec --issue` / `apply` as the intake controller (rejected: no batch, no docs PR, mandatory handoff for covered classes).
