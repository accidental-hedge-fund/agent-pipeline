## Purpose

Retire the leftover committed `plugin/` packaging surface after the CLI install path shipped. The repository has no `plugin/` tree, generators do not write one, and Claude install remains `install --host claude`.

## ADDED Requirements

### Requirement: The repository SHALL NOT contain a plugin directory

The committed repository tree SHALL NOT include a `plugin/` directory. Whole-tree deletion is the deliverable. An empty `plugin/` directory, a SKILL-only shell, or a marketplace bridge launcher under `plugin/` SHALL NOT remain.

#### Scenario: plugin/ is absent from the committed tree

- **WHEN** the committed repository tree is listed at the repository root
- **THEN** no `plugin/` directory SHALL exist
- **AND** no path SHALL start with `plugin/`

#### Scenario: empty stub is not acceptable

- **WHEN** a generate or commit would leave an empty `plugin/` directory
- **THEN** that tree SHALL NOT be committed
- **AND** the change SHALL NOT treat an empty directory as deletion complete

### Requirement: Build and install SHALL NOT write a repository plugin tree

`scripts/build.mjs` and `scripts/install.mjs` SHALL NOT create, copy, or write any path under a repository-root `plugin/` directory. After a successful generate run, the output root SHALL NOT contain `plugin/`. Dual-ship of a plugin SKILL overlay, marketplace bridge, or core copy is forbidden.

#### Scenario: generate does not recreate plugin/

- **WHEN** `node scripts/build.mjs` runs (including generate-into-temp)
- **THEN** the output root SHALL NOT contain a `plugin/` directory
- **AND** SHALL NOT contain `plugin/pipeline/skills/pipeline/SKILL.md`

#### Scenario: install does not write repo plugin/

- **WHEN** `scripts/install.mjs` runs `install --host claude` (not dry-run)
- **THEN** it SHALL NOT create a repository-root `plugin/` tree
- **AND** it SHALL still provision the managed Claude skill tree from `core/` plus host SKILL

### Requirement: build check SHALL NOT require a plugin overlay

`node scripts/build.mjs --check` SHALL exit non-zero when any generated host SKILL (`hosts/claude/SKILL.md`, `hosts/codex/SKILL.md`, `hosts/grok/SKILL.md`, or `hosts/opencode/SKILL.md`) differs from a fresh generation. It SHALL NOT require a plugin SKILL overlay. Absence of `plugin/` SHALL NOT by itself fail `--check`.

#### Scenario: matching host SKILLs pass without plugin/

- **WHEN** the four generated host SKILLs match their fresh generated bytes
- **AND** `plugin/` is absent
- **THEN** `node scripts/build.mjs --check` SHALL exit 0

#### Scenario: stale host SKILL fails check

- **WHEN** any of the four committed host SKILLs differs from a fresh generation
- **THEN** `node scripts/build.mjs --check` SHALL exit non-zero and name the stale exact path

#### Scenario: absent plugin overlay does not fail check

- **WHEN** `plugin/pipeline/skills/pipeline/SKILL.md` is absent
- **AND** the four host SKILLs match a fresh generation
- **THEN** `--check` SHALL NOT fail solely because that overlay is missing

### Requirement: Marketplace catalog SHALL NOT advertise a plugin/ source

The repository SHALL NOT list a Claude marketplace plugin whose `source` is `./plugin/pipeline` or any other path under `plugin/`. `scripts/build.mjs` SHALL NOT write such an entry. If `.claude-plugin/marketplace.json` remains, it SHALL NOT restore a `plugin/` source. If that catalog’s only remaining purpose is advertising the deleted plugin, the catalog file SHALL be removed and SHALL NOT be regenerated.

#### Scenario: catalog does not source plugin/

- **WHEN** `.claude-plugin/marketplace.json` is present after this change
- **THEN** no listed plugin SHALL have a source path under `plugin/`

#### Scenario: generator does not emit a plugin/ catalog listing

- **WHEN** `node scripts/build.mjs` runs
- **THEN** it SHALL NOT write a catalog entry with source `./plugin/pipeline`
- **AND** it SHALL NOT create a replacement marketplace stub directory in place of `plugin/`

### Requirement: CI SHALL dogfood Claude CLI install without plugin/

The repository CI surface (`npm run ci`, including install smoke) SHALL run an isolated `install --host claude` into a temp config dir and SHALL invoke the installed launcher as `doctor` and `status <N>`. Those verbs SHALL dispatch as CLI keywords. They SHALL NOT require a repo `plugin/` tree or a `/pipeline status` slash command.

#### Scenario: isolated install dispatches doctor and status

- **WHEN** CI or install smoke runs `install --host claude` in a temp config dir
- **AND** the installed launcher is invoked as `doctor`
- **THEN** the CLI SHALL dispatch the doctor verb
- **AND** when invoked as `status <N>` it SHALL dispatch the status verb
- **AND** neither invocation SHALL fail because `plugin/` is absent
- **AND** neither invocation SHALL require `/pipeline status`

#### Scenario: repo plugin/ is not a CI install input

- **WHEN** the install-smoke tree has no `plugin/` directory
- **THEN** `install --host claude` SHALL still provision the managed skill from `core/` and host SKILL
- **AND** SHALL NOT fail solely because the leftover plugin shell is missing

### Requirement: Packaging docs SHALL name CLI plus SKILL and leftover CLAUDE_PLUGIN_ROOT migration

Contributor-facing packaging docs (`docs/packaging.md`, and README Development when it speaks about consumption) SHALL present install CLI plus short SKILL as the product path. They SHALL NOT describe a remaining generated `plugin/` shell. They SHALL tell an operator whose `CLAUDE_PLUGIN_ROOT` still points at a leftover core copy to run `install --host claude` or pin. Repo-root `AGENTS.md` and `CLAUDE.md` golden rule #1 SHALL name CLI plus short SKILL and SHALL NOT tell contributors to commit `plugin/`.

#### Scenario: packaging page has no remaining plugin shell

- **WHEN** a contributor reads `docs/packaging.md`
- **THEN** the page SHALL tell them to install the CLI and a short host SKILL
- **AND** it SHALL NOT describe `plugin/` as a current generated overlay or distribution product

#### Scenario: leftover core-copy migration is named

- **WHEN** an operator still has `CLAUDE_PLUGIN_ROOT` pointing at a leftover plugin core copy
- **THEN** packaging or install docs SHALL tell them to run `install --host claude` or pin

#### Scenario: golden rule does not commit plugin/

- **WHEN** a contributor reads `AGENTS.md` or `CLAUDE.md` golden rule #1
- **THEN** the rule SHALL name CLI plus short SKILL as the product
- **AND** SHALL NOT tell them to commit `plugin/` or a plugin core mirror

### Requirement: Recreating plugin/ SHALL fail tests

A co-located or scripts-level test SHALL fail when `scripts/build.mjs` writes any path under `plugin/`. A test SHALL fail when `--check` requires a plugin SKILL overlay to pass. Those tests SHALL inject filesystem I/O and SHALL NOT use real network or git beyond existing isolated install-smoke fixtures.

#### Scenario: generate-into-temp fails if plugin/ returns

- **WHEN** a generate-into-temp test runs after `build.mjs` writes `plugin/pipeline/skills/pipeline/SKILL.md`
- **THEN** the test SHALL fail

#### Scenario: check-requires-overlay fails the guard

- **WHEN** `--check` exits non-zero solely because `plugin/` is absent while host SKILLs match
- **THEN** the freshness-without-plugin test SHALL fail
